# Agent memory systems — research for Morz memory v2 (2026-07-24)

Five systems studied internally (Honcho, mem0, Letta/MemGPT, Zep/Graphiti, Claude Code + procedural-learning literature). Through-line: **everyone converges on "store cheap, consolidate offline, retrieve narrow"; they differ on how much LLM machinery sits on the write path. Morz stays lean there because it has the one thing none of them have: a human approval gate.** The markdown-per-fact + FTS5 + approval-gated store (0.0.4) is the right substrate — layer upgrades, don't replace.

## Per-system: what to steal / what to avoid

| System | Core mechanism | STEAL | AVOID |
|---|---|---|---|
| **Honcho** (Plastic Labs; Hermes uses it) | Store raw messages; background "deriver" (1 cheap LLM call/batch) + idle "Dreamer" build a theory-of-mind model; Dialectic API answers NL questions about the user | `(observer, observed)` collection key (generalizes agent scope for multi-agent); explicit-vs-derived trust tiers; "query the store in NL as an expert on the user" read pattern | Postgres+Redis+two daemons; continuous background LLM spend; AGPL; psych-profiling scope creep |
| **mem0** | Two-phase write: LLM extracts facts → per fact, retrieve top-10 similar → LLM emits **ADD/UPDATE/DELETE/NOOP** (the LLM is the deduplicator); SQLite audit history | **The op-set as approval payload** (user approves "UPDATE #12: old→new", not blind appends); `hash` pre-dedup; SQLite audit log; `infer=false` fast path; relative-date normalization | 2 LLM calls per turn (batch instead); silent auto-DELETE; graph variant; chit-chat-tuned extraction prompts (rewrite for coding) |
| **Letta / MemGPT** | Memory tiers (core in-context blocks / archival vector / recall log); blocks = `{label, description, value, limit, read_only}`, **ID-addressable + shared across agents**; sleep-time agent consolidates offline | **Shared blocks = Morz `space` scope**: orchestrator + team attach to ONE space block, promoted facts hit every teammate's launch prompt; `read_only` for locked facts; "a pinned block IS a CLAUDE.md"; opt-in idle consolidation | Docker server + Postgres/pgvector; memory-editing on the latency path (Letta walked it back); second always-on agent; lossy auto-summarization |
| **Zep / Graphiti** | Temporal knowledge graph; every fact carries `created_at/expired_at` (system knowledge) + `valid_at/invalid_at` (world truth); contradictions soft-invalidate (old edge kept + rewritten "used to…"); no-LLM hybrid retrieval (cosine+BM25+RRF) | **Bi-temporal fields + soft-invalidation + provenance (`source_run_id`)** — near-free in SQLite; inject facts WITH validity window ("we used X until commit Y, now Z"); FTS5+vector+RRF retrieval with zero LLM calls | The graph DB itself; 6–15 LLM calls per write; community/cluster layer; LLM reranking by default. Steal the data model, reject the infrastructure |
| **Claude Code + procedural lit** (Voyager, Generative Agents, ReasoningBank, Memp) | CLAUDE.md hierarchy (managed→user→project→local) + auto-memory MEMORY.md index (~200-line budget) + topic files; `@` imports; rules with path globs. Skills: store only after verified success; score by frequency × recency-decay × relevance; `{Title, Description, Content}` cards; Add/Correct/Deprecate by success rate | Render ONE canonical store into each CLI's file (CLAUDE.md / **AGENTS.md** for Codex+agy / GEMINI.md — no single shared filename exists; AGENTS.md is the de-facto standard, per-tool shims import it); index + budget + on-demand topic files; **frequency × recency × success promotion** for "which tools/skills the user actually uses" | Treating injected markdown as enforcement (hard rules → hooks); unbounded index growth; promoting one-offs or repeated FAILING patterns |

## Recommended Morz architecture (priority order)

1. **Op-set reconciliation (mem0)** — candidate write → top-k same-scope retrieval → ADD/UPDATE/DELETE/NOOP → the op IS the approval card. Hash pre-dedup. Stops duplicate/contradiction accretion. Tiny surface, pure win.
2. **Bi-temporal schema (Zep)** — add `valid_at/invalid_at/created_at/expired_at/source_run_id` per fact; contradictions expire rows, never delete; invalidation is itself an approvable write (free undo + audit); inject validity windows.
3. **Per-CLI rendering + shared space blocks (Letta + Claude Code)** — canonical facts stored once, rendered at launch into CLAUDE.md / AGENTS.md / GEMINI.md (managed `<!-- morz:memory -->` blocks — merges with context-hub); `space` scope = shared block for whole dispatched team; `read_only` blocks for locked brand/design facts; ~200-line index budget.
4. **Procedural learning (phased last)** — log CLI/tool/skill invocations + outcomes; score frequency × recency-decay × success-rate; at threshold PROPOSE a `{Title, Description, Content}` card ("prefers Codex for refactors", induced coding standards). Hard rules: verify before persist; count+recency threshold; never promote failing patterns.

**Rejected outright:** graph DBs, Postgres/Redis, always-on daemons, LLM calls on the latency-critical path, unapproved store mutation. Heavy systems are heavy because they lack a human in the loop; Morz has one by design.

**Confidence notes:** Honcho temporal-revision semantics + Zep per-episode call counts are inferred; scoring formulas from A-MEM/Memp/ReasoningBank summarized from PDFs — confirm before hard-coding.
